# Customer Relationship Management (CRM) System

A small Salesforce CRM portfolio project for managing Customers, Leads and Follow-Ups.

## Features
- Customer, Lead and Follow-Up custom objects
- Lookup relationship: Follow-Up -> Customer
- Validation rules and formula fields
- Record-triggered and scheduled Flow concepts
- Apex controller, trigger and test class
- Lightning Web Component customer dashboard
- Reports and dashboard documentation
- Salesforce DX + Git/GitHub ready structure

## Project Structure
```text
force-app/main/default/
├── objects/
├── classes/
├── triggers/
├── flows/
└── lwc/customerDashboard/
```

## Apex
`CRMController` retrieves customers and total customer count using SOQL.
`CustomerTrigger` sets Status to New when Status is blank.
`CRMControllerTest` tests the controller and trigger.

## LWC
`customerDashboard` displays total customers and a customer table.

## Deployment
```bash
sf org login web --alias CRMDev
sf project deploy start --source-dir force-app --target-org CRMDev --dry-run
sf project deploy start --source-dir force-app --target-org CRMDev
```

## Important
Flow, Report, Dashboard, and UI-created metadata should be retrieved from your Salesforce org after you create/configure them, so the repository contains the exact metadata generated by your org.

## Included Metadata

This repository now includes metadata files for:
- Customer__c, Lead__c and Follow_Up__c custom objects
- Custom fields and picklists
- Customer and Follow-Up validation rules
- Formula fields
- CRM status automation Flow
- Follow-up reminder Flow configuration

Reports and Dashboards are documented under `docs/REPORTS_AND_DASHBOARD.md`; retrieve them from the target org if you want the exact generated metadata.

## Metadata Validation

Before deploying to a real org, run a dry-run deployment and Apex tests. If Salesforce reports an API-version or Flow-schema difference, retrieve the corresponding component from the target org with the Salesforce CLI and commit the generated metadata.
